# Django-проект `config` — домашнее задание (урок 44)

Учебный проект по уроку «Установка и структура Django-фреймворка».
Внутри — проект `config` и два приложения: `blog` и `users`.

## Быстрый старт

```bash
# 1. Создать и активировать виртуальное окружение
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS / Linux

# 2. Установить зависимости
pip install -r requirements.txt

# 3. Применить миграции
python manage.py migrate

# 4. Запустить сервер
python manage.py runserver
```

После запуска:

* http://127.0.0.1:8000/ — главная страница с ответом `Привет, Django!`;
* http://127.0.0.1:8000/admin/ — стандартная админка Django.

## Структура проекта

```
config/                 # проект целиком (настройки и корневые маршруты)
├── manage.py           # утилита управления проектом
├── config/
│   ├── settings.py     # настройки: приложения, БД, язык, таймзона, статика
│   ├── urls.py         # главные маршруты проекта
│   ├── asgi.py         # точка входа для ASGI-серверов
│   └── wsgi.py         # точка входа для WSGI-серверов
├── blog/               # приложение «блог»
│   ├── models.py       # модели (таблицы БД)
│   ├── views.py        # логика обработки запросов
│   ├── admin.py        # регистрация моделей в админке
│   └── migrations/     # история изменений схемы БД
└── users/              # приложение «пользователи»
```

## Назначение файлов (уровень 2)

| Файл | Назначение |
|------|------------|
| `manage.py` | Утилита командной строки: запускает сервер, создаёт миграции, применяет их и выполняет другие команды управления проектом. |
| `config/settings.py` | Главный файл настроек: список приложений, подключение к базе данных, язык, часовой пояс, статика и прочие параметры. |
| `config/urls.py` | Корневая таблица маршрутов: сопоставляет URL-адреса с представлениями и подключает маршруты приложений. |
| `blog/models.py` | Модели приложения — Python-классы, которые Django превращает в таблицы базы данных. |
| `blog/views.py` | Представления — функции или классы, обрабатывающие запросы и возвращающие ответы. |
| `blog/admin.py` | Регистрация моделей в административной панели Django, чтобы их можно было просматривать и редактировать. |
| `blog/migrations/` | История миграций: файлы с описанием изменений схемы БД, созданные по моделям. |

## Настройки проекта

В `config/settings.py`:

* `blog` и `users` добавлены в `INSTALLED_APPS`;
* `LANGUAGE_CODE = "ru"` — русский язык интерфейса;
* `TIME_ZONE = "Asia/Tashkent"` — часовой пояс Ташкента.

## Почему логику делят на приложения

Проект — это весь сайт, а приложение — отдельная его часть, отвечающая за одну
зону ответственности (магазин, блог, пользователи). Такое деление даёт:

* **изоляцию кода** — модели, шаблоны и маршруты каждой части лежат рядом;
* **переиспользование** — приложение можно перенести в другой проект почти без изменений;
* **лёгкую поддержку** — проще найти нужный код и не сломать соседние части;
* **командную работу** — разные люди могут работать над разными приложениями;
* **гибкость** — ненужное приложение отключается одной строкой в `INSTALLED_APPS`.
